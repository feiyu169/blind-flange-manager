# Gateflow 工作流优化方案

## 背景

基于盲板管理系统项目的执行经验，发现 gateflow 工作流存在以下问题：
- 问题发现得太晚，修复成本高
- 代码质量检查不够严格
- 安全审查不够深入
- 文档策略不够明确

## 讨论参与者

- 项目开发者
- 第三方审查专家
- 用户

## 核心决定

### 1. 文档策略（三方一致同意）

**结论**：文档先行应该详尽，但需要分层管理。

**分层文档策略**：

**第一层：核心文档（必须详尽）**
- 需求文档：用户故事、验收标准、边界条件
- 架构设计文档：架构图、技术选型理由、接口设计
- 安全设计文档：认证方案、授权方案、密钥管理

**第二层：辅助文档（可以简化）**
- ADR：只记录关键决策（不超过4个）
- API 文档：Swagger 自动生成
- 测试计划：checklist 形式

**第三层：临时文档（按需创建）**
- 会议记录
- 讨论记录
- 决策记录

**文档管理策略**：
- 核心文档是"活的文档"，可以迭代更新
- 核心文档和代码一起版本控制
- 代码变更时，强制检查文档是否需要更新

### 2. 代码审查门禁（三方一致同意）

**结论**：采用"自动化 + 人工"组合，pre-commit hook。

**自动化检查项**：
- P0（必须）：安全扫描（bandit）、测试覆盖率（pytest --cov）
- P1（强烈建议）：代码规范（ruff）、类型检查（mypy）
- P2（可选）：性能测试、依赖漏洞（safety）

**人工检查项**：
- 架构合理性
- 业务逻辑正确性
- 安全设计合理性

### 3. 安全审查专项（三方一致同意）

**结论**：安全审查应该独立，采用"持续安全审查 + 安全冠军制度"。

**安全审查阶段**：
1. 设计阶段：安全设计评审
2. 实施阶段：安全编码检查
3. 发布前：安全扫描
4. 运行时：安全监控

**安全冠军职责**：
- 设计阶段：参与安全设计评审
- 实施阶段：检查安全编码
- 发布前：执行安全扫描
- 运行时：监控安全事件

### 4. 预检阶段（三方一致同意）

**结论**：增加轻量级技术可行性快速检查（30分钟）。

**检查内容**：
- 技术栈兼容性（5分钟）
- 依赖库版本（5分钟）
- 安全基线（10分钟）
- 架构约束（10分钟）

### 5. 架构验证（三方一致同意）

**结论**：分为两个层面：
1. 计划阶段：架构设计评审（预防）
2. 实施阶段：架构一致性检查（检测）

### 6. 自动化门禁（三方一致同意）

**结论**：分优先级实施。

**优先级**：
- P0（必须）：安全扫描、测试覆盖率
- P1（强烈建议）：代码规范、类型检查
- P2（可选）：性能测试、依赖漏洞

### 7. 迭代回顾（三方一致同意）

**结论**：轻量级异步文档（15-30分钟）。

**回顾内容**：
- 什么做得好？
- 什么可以改进？
- 下次怎么做？

### 8. 质量评分（三方一致同意）

**结论**：改为"质量健康度检查"，作为诊断工具，非考核指标。

### 9. 第三方评估（三方一致同意）— 新增

**结论**：在 ready-to-create-PR 之后、创建 PR 之前，进行第三方资深专家评估。评估后进行至少三轮讨论，对 P0/P1 事项逐项讨论，直至达成一致。

**评估流程**：
```
ready-to-create-PR
    ↓
【第三方评估】← 资深专家评估，30-60分钟
    ↓
第一轮：开发者回应评估问题
    ↓
第二轮：专家回应并提出建议
    ↓
第三轮：双方达成共识
    ↓
【逐项讨论】
    ↓
P0 事项逐项讨论（每项至少一轮，最多三轮）
    ↓
P1 事项逐项讨论（每项至少一轮，最多三轮）
    ↓
（如果未达成共识，继续讨论，最多五轮）
    ↓
提交评估报告
    ↓
创建 PR
```

**评估边界条件**：

| 条件 | 规则 |
|------|------|
| 评估时机 | ready-to-create-PR 之后、创建 PR 之前 |
| 讨论目的 | 澄清事实，达成共识 |
| 讨论范围 | P0 和 P1 事项必须逐项讨论，P2 事项可以跳过 |
| 讨论顺序 | 先讨论 P0 事项，再讨论 P1 事项 |
| 讨论轮数 | 每项至少讨论一轮，最多三轮 |
| 讨论结果 | 每项必须达成一致意见，否则记录为"未达成一致" |

**评估结果**：
- PASS：无阻断问题，可直接创建 PR
- PASS_WITH_TODO：有改进问题，创建 PR + 记录改进项
- FAIL：有阻断问题，必须修复后重新评估

**阻断条件**（必须修复）：
- P0 安全问题（硬编码密钥、无认证）
- P0 架构问题（数据库选型错误）
- 测试覆盖率 < 50%

**不阻断条件**（记录为改进项）：
- P1/P2 问题
- 文档不完整
- 代码规范问题

## 优化后的 gateflow 流程

```
需求澄清
    ↓
【预检阶段】← 新增（轻量级技术可行性快速检查，30分钟）
    ↓
计划制定（含核心文档：需求文档、架构设计文档、安全设计文档）← 强化
    ↓
计划审查
    ↓
切片实施
    ↓
【架构验证】← 新增（架构一致性检查）
    ↓
代码审查（含自动化门禁）← 强化
    ↓
【安全审查专项】← 新增（持续安全审查）
    ↓
深度审查
    ↓
优化迭代
    ↓
【迭代回顾】← 新增（轻量级异步文档，15-30分钟）
    ↓
【质量健康度检查】← 新增（诊断工具，非考核指标）
    ↓
【第三方评估】← 新增（资深专家评估 + 三轮讨论 + 逐项讨论P0/P1）
    ↓
创建 PR
```
