# 质量健康度检查模板

## 概述

质量健康度检查是诊断工具，用于识别问题，而不是评判好坏。在发布前执行，输出质量健康度报告。

## 检查维度

### 1. 代码质量（权重：30%）

**检查指标**：
- ruff 错误数
- 类型注解完整度
- 代码复杂度
- 代码重复率

**评分标准**：
- 90-100%：优秀（ruff 错误 = 0，类型注解完整）
- 70-89%：良好（ruff 错误 < 5，类型注解基本完整）
- 50-69%：一般（ruff 错误 < 10，类型注解部分缺失）
- <50%：需要改进（ruff 错误 > 10，类型注解严重缺失）

### 2. 安全性（权重：30%）

**检查指标**：
- 安全扫描结果
- 认证完整性
- 密钥管理
- 依赖漏洞

**评分标准**：
- 90-100%：优秀（无高危漏洞，认证完整）
- 70-89%：良好（无高危漏洞，认证基本完整）
- 50-69%：一般（有中危漏洞，认证部分缺失）
- <50%：需要改进（有高危漏洞，认证严重缺失）

### 3. 文档完整性（权重：20%）

**检查指标**：
- ADR 数量
- API 文档覆盖率
- README 完整度
- 代码注释覆盖率

**评分标准**：
- 90-100%：优秀（ADR ≥ 4，API 文档完整，README 详细）
- 70-89%：良好（ADR ≥ 2，API 文档基本完整，README 基本详细）
- 50-69%：一般（ADR ≥ 1，API 文档部分缺失，README 简单）
- <50%：需要改进（无 ADR，API 文档严重缺失，README 不完整）

### 4. 测试覆盖（权重：20%）

**检查指标**：
- 测试覆盖率
- 测试通过率
- 边界测试
- 集成测试

**评分标准**：
- 90-100%：优秀（覆盖率 > 80%，通过率 100%）
- 70-89%：良好（覆盖率 > 70%，通过率 > 95%）
- 50-69%：一般（覆盖率 > 60%，通过率 > 90%）
- <50%：需要改进（覆盖率 < 60%，通过率 < 90%）

## 输出格式

```
质量健康度报告：
- 代码质量: [分数]% ([评级])
- 安全性: [分数]% ([评级])
- 文档完整性: [分数]% ([评级])
- 测试覆盖: [分数]% ([评级])

综合评分: [分数]% ([评级])

建议优先改进: [类别]
```

## 评分标准

| 评分 | 评级 | 说明 |
|------|------|------|
| 90-100% | 优秀 | 可直接发布 |
| 70-89% | 良好 | 可发布但需改进 |
| 50-69% | 一般 | 需改进后发布 |
| <50% | 需要改进 | 需重新开发 |
