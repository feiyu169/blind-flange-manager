# ADR-002: 开发环境使用 SQLite

## 状态

接受

## 背景

项目需要选择开发环境的数据库。主要候选方案：
- PostgreSQL（生产环境）
- SQLite（开发环境）
- MySQL

项目需求：
1. 开发环境快速启动
2. 生产环境稳定性
3. 数据库迁移支持
4. 测试环境隔离

## 决策

开发环境使用 **SQLite**，生产环境使用 **PostgreSQL**。

## 理由

### SQLite 优势（开发环境）

1. **零配置**
   - 无需安装和配置数据库服务
   - 单文件数据库，便于管理
   - 适合快速原型开发

2. **快速启动**
   - 无需等待数据库服务启动
   - 适合单元测试和集成测试
   - 开发环境重启成本低

3. **便于分享**
   - 数据库文件可以随代码提交（开发环境）
   - 便于团队成员快速搭建环境

### PostgreSQL 优势（生产环境）

1. **性能**
   - 支持高并发
   - 查询优化器成熟
   - 支持复杂查询

2. **功能**
   - 原生 JSON/JSONB 支持
   - 丰富的数据类型
   - 事务隔离级别完善

3. **可靠性**
   - ACID 完整支持
   - 数据一致性保证
   - 成熟的备份恢复方案

## 后果

### 正面影响

- 开发环境快速启动
- 测试环境隔离
- 生产环境稳定

### 负面影响

- 需要维护两套数据库配置
- SQLite 和 PostgreSQL 行为差异需要测试
- 需要 Alembic 管理数据库迁移

## 缓解措施

1. **使用 Alembic 管理迁移**
   - 统一的数据库迁移脚本
   - 支持 SQLite 和 PostgreSQL
   - 版本控制数据库结构

2. **测试环境使用 SQLite**
   - 单元测试使用 SQLite
   - 集成测试使用 PostgreSQL（CI）
   - 避免数据库差异导致的问题

3. **文档说明**
   - README 中说明数据库配置
   - .env.example 提供配置模板
   - ADR 记录决策理由
